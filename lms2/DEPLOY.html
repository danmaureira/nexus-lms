Arquitectura del sistema

¿Qué tipo de sistema es Nexus LMS?

La versión actual es un frontend estático (HTML + CSS + JS puro). Funciona sin servidor de base de datos real — los datos viven en el navegador. Esto es perfecto para demos y pilotos.

⚠️ Para un despliegue de producción con 300+ usuarios reales, necesitarás una capa de backend con base de datos real. El instructivo cubre dos caminos: (A) versión estática mejorada con Firebase y (B) versión con servidor propio.

Stack recomendado para producción:

  • Frontend: HTML/CSS/JS estático (este proyecto) o React
  • Autenticación: Google OAuth 2.0 (Firebase Auth o Auth directa)
  • Base de datos: Firebase Firestore (opción sin servidor) o PostgreSQL (servidor propio)
  • Almacenamiento archivos: Firebase Storage o Amazon S3
  • Hosting: Firebase Hosting, Vercel, VPS (Render, Railway, DigitalOcean)
A

Opción A — Firebase (recomendado para equipos sin servidor propio)

¿Por qué Firebase?

Firebase es una plataforma de Google que ofrece base de datos en tiempo real, autenticación con Google, almacenamiento de archivos y hosting — todo sin administrar servidores. El plan gratuito (Spark) soporta hasta ~50k lecturas/día.

✅ Tiempo estimado de configuración: 2-3 horas · Costo: Gratis para empezar, ~$25 USD/mes si supera cuotas gratuitas

Paso A.1 — Crear proyecto Firebase

  1. Ve a console.firebase.google.com e inicia sesión con Google
  2. Clic en Agregar proyecto → Nombre: nexus-lms-tu-institucion
  3. Desactiva Google Analytics (opcional) → Crear proyecto

Paso A.2 — Habilitar Google Authentication

  1. En la consola Firebase, ve a Authentication → Sign-in method
  2. Habilita Google como proveedor
  3. Agrega tu dominio en Authorized domains (ej: cursos.tuinstitucion.cl)
  4. Copia el Web client ID — lo necesitarás en el código
El Web Client ID tiene el formato: 1234567890-abc.apps.googleusercontent.com
Reemplázalo en js/core.js en la variable NexusDB.platform.googleClientId

Paso A.3 — Configurar Firestore (base de datos)

  1. Ve a Firestore Database → Crear base de datos
  2. Selecciona Modo de producción
  3. Elige región: us-central1 (o southamerica-east1 para menor latencia desde Chile)
  4. En Reglas, establece:
rules_version = '2'; service cloud.firestore { match /databases/{database}/documents { match /users/{userId} { allow read: if request.auth != null; allow write: if request.auth.uid == userId || get(/databases/$(database)/documents/users/$(request.auth.uid)).data.role == 'admin'; } match /courses/{courseId} { allow read: if request.auth != null; allow write: if get(/databases/$(database)/documents/users/$(request.auth.uid)).data.role in ['admin', 'teacher']; } match /submissions/{subId} { allow read: if request.auth != null; allow create: if request.auth != null; allow update: if get(/databases/$(database)/documents/users/$(request.auth.uid)).data.role in ['admin', 'teacher']; } } }

Paso A.4 — Desplegar en Firebase Hosting

  1. Instala Firebase CLI: npm install -g firebase-tools
  2. Inicia sesión: firebase login
  3. En la carpeta del proyecto: firebase init hosting
  4. Selecciona tu proyecto → Directorio público: . (punto) → SPA: No
  5. Despliega: firebase deploy
  6. Tu sitio quedará en: nexus-lms-xxxx.web.app
# Instalar y desplegar (terminal) npm install -g firebase-tools firebase login firebase init hosting firebase deploy # Para redespliegues posteriores: firebase deploy --only hosting

Opción B — VPS con servidor propio (máximo control)

¿Qué es un VPS?

Un VPS (Virtual Private Server) es un servidor virtual dedicado. Tienes control total: puedes instalar cualquier software, gestionar base de datos propia y escalar cuando quieras. Es la opción más robusta.

Institucional

🏫 Servidor institucional

Si tu institución tiene servidor web con Apache/Nginx, sube los archivos por FTP/SFTP. Consulta con TI.

Paso B.1 — Subir los archivos (versión estática sin backend)

Para la versión estática (demo/piloto), cualquier hosting de archivos estáticos funciona:

  1. Comprime la carpeta lms2/ en un ZIP
  2. Sube los archivos por FTP/SFTP al directorio público del servidor (ej: /var/www/html/lms/ en Apache, o /usr/share/nginx/html/lms/ en Nginx)
  3. El sitio estará accesible en http://tu-servidor/lms/

Paso B.2 — Configurar Nginx (servidor web)

# Instalar Nginx en Ubuntu/Debian sudo apt update && sudo apt install -y nginx # Crear configuración del sitio sudo nano /etc/nginx/sites-available/nexus-lms # Pegar esta configuración: server { listen 80; server_name cursos.tuinstitucion.cl www.cursos.tuinstitucion.cl; root /var/www/nexus-lms; index index.html; location / { try_files $uri $uri/ /index.html; } # Comprimir archivos para mejor rendimiento gzip on; gzip_types text/css application/javascript text/html; } # Activar configuración sudo ln -s /etc/nginx/sites-available/nexus-lms /etc/nginx/sites-enabled/ sudo nginx -t && sudo systemctl reload nginx
2

Configurar dominio personalizado

Paso 2.1 — Apuntar el dominio al servidor

En el panel de gestión de tu dominio (NIC Chile, GoDaddy, Namecheap, etc.), crea un registro DNS:

Tipo: A Host: cursos (o @ para dominio raíz) Valor: [IP de tu servidor o IP de Firebase/Vercel] TTL: 3600 # O si usas Firebase/Vercel/Netlify, usa CNAME: Tipo: CNAME Host: cursos Valor: tu-proyecto.web.app (Firebase) cname.vercel-dns.com (Vercel) TTL: 3600

Los cambios DNS pueden tardar 15 minutos a 48 horas en propagarse globalmente.

Paso 2.2 — Habilitar HTTPS (SSL gratuito)

HTTPS es obligatorio para que Google OAuth funcione. Usa Let's Encrypt (gratis):

# Instalar Certbot sudo apt install -y certbot python3-certbot-nginx # Obtener certificado SSL automáticamente sudo certbot --nginx -d cursos.tuinstitucion.cl -d www.cursos.tuinstitucion.cl # El certificado se renueva automáticamente cada 90 días # Para verificar renovación automática: sudo systemctl status certbot.timer
✅ Después de esto, tu plataforma estará en: https://cursos.tuinstitucion.cl con candado verde.

Paso 2.3 — Agregar dominio a Google OAuth

  1. Ve a console.cloud.google.com
  2. Selecciona tu proyecto → APIs y servicios → Credenciales
  3. Edita tu credencial OAuth 2.0
  4. En Orígenes de JavaScript autorizados, agrega: https://cursos.tuinstitucion.cl
  5. En URIs de redireccionamiento autorizados, agrega: https://cursos.tuinstitucion.cl/oauth-callback
  6. Guarda los cambios (tardan ~5 minutos en aplicarse)
3

Activar Google Sign-In real (producción)

Paso 3.1 — Crear credenciales OAuth en Google Cloud

  1. Ve a console.cloud.google.com
  2. Crea un proyecto nuevo o selecciona el existente
  3. Ve a APIs y servicios → Pantalla de consentimiento OAuth → Configura la pantalla con nombre de tu institución
  4. Ve a Credenciales → Crear credenciales → ID de cliente OAuth 2.0
  5. Tipo: Aplicación web
  6. Copia el Client ID generado

Paso 3.2 — Reemplazar mock por Google Sign-In real

En index.html, reemplaza el botón de Google con el SDK oficial:

<!-- Agregar en <head> --> <script src="https://accounts.google.com/gsi/client" async defer></script> <!-- Reemplazar el botón manual con: --> <div id="g_id_onload" data-client_id="TU_CLIENT_ID.apps.googleusercontent.com" data-callback="handleGoogleLogin" data-auto_prompt="false"> </div> <div class="g_id_signin" data-type="standard" data-size="large" data-theme="outline"></div> <script> function handleGoogleLogin(response) { // Decodificar JWT de Google const payload = JSON.parse(atob(response.credential.split('.')[1])); const { email, name, picture, sub } = payload; // Buscar usuario en tu DB o crear nuevo let user = NexusDB.getUserByEmail(email); if (!user) { user = { id: "u"+Date.now(), googleId: sub, name, email, avatar: picture, role: "student", enrolledCourses: [], progress: {}, createdAt: new Date().toISOString().split("T")[0] }; NexusDB.users.push(user); } else { user.avatar = picture; // actualizar foto } saveSession(user); redirectByRole(user); } </script>

Persistencia de datos (para producción real)

Solución A: Firebase Firestore (recomendado, sin servidor)

Reemplaza NexusDB con llamadas a Firestore:

// Agregar SDK de Firebase en <head> import { initializeApp } from 'https://www.gstatic.com/firebasejs/10.0.0/firebase-app.js'; import { getFirestore, collection, getDocs, addDoc } from 'https://www.gstatic.com/firebasejs/10.0.0/firebase-firestore.js'; const app = initializeApp({ apiKey: "...", authDomain: "...", projectId: "..." }); const db = getFirestore(app); // Cargar cursos const coursesSnap = await getDocs(collection(db, "courses")); const courses = coursesSnap.docs.map(d => ({ id: d.id, ...d.data() })); // Guardar entrega await addDoc(collection(db, "submissions"), { ...submissionData });

Checklist de lanzamiento

Antes de compartir la URL con tus usuarios:

  • ☐ Dominio configurado con HTTPS activo (candado verde en navegador)
  • ☐ Google OAuth funciona — haz login con tu cuenta Google en el sitio real
  • ☐ Branding configurado — logo, nombre institución y colores aplicados
  • ☐ Cursos creados con módulos y recursos publicados
  • ☐ Usuarios importados y asignados a cursos
  • ☐ URLs de Zoom cargadas en sesiones sincrónicas
  • ☐ Prueba de entrega — entra como estudiante demo y envía una actividad
  • ☐ Prueba de calificación — entra como admin/docente y califica la entrega anterior
